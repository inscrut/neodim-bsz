## 3. Форматирование страниц

### 3.1. Заголовки

- Первый H1 — название страницы + встроенная ссылка-якорь: `{#page-slug}`
  ```markdown
  # Название страницы {#anchor-name}
  ```
- Все последующие заголовки (H2–H4) также с якорями.
- Якорь должен иметь осмысленное имя на английском: `#single-circuit-system`, `#distributor-new-173706`.

### 3.2. Изображения

- Все пути **относительные** от расположения файла (`../assets/wiki/...` или `assets/wiki/...` если на одном уровне).
- Всегда указывайте ширину: `width="360"` или `width="720"`.
- Типы файлов: предпочтительно `webp`, затем `jpg`, `PNG`.
- Пример:
  ```markdown
  ![Описание картинки](../assets/wiki/distributors/r-114/kit.webp){ width="360" }
  ```

### 3.3. Ссылки

- Используются **относительные пути** к `.md` файлам в рамках `docs/`.
- Пример: `[Название](guide/schemes/single-circuit.md)` или `../../components/buy-list.md`.
- Внешние ссылки — полные URL: `https://ozon.ru/...`.
- Артурные ссылки — полные URL с `search?text=...`.

### 3.4. Таблицы

- Использовать для спецификаций комплектов (SKU, артикул, версия, материал, совместимость).
- Заголовок таблицы должен содержать осмысленные имена колонок.
- SKU и артикул поиска выделять **жирным**.

### 3.5. Гриды карточек

```markdown
<div class="grid cards" markdown>
-   :material-icon-name: **[Название](путь.md)**

    Краткое описание (1-2 строки).
</div>
```

### 3.6. Сниппеты (VK-виджеты, Telegram)

Вставлять через:
```markdown
--8<-- "snippets/filename.md"
```

### 3.7. Tip/Note/Warning/Admonitions

```markdown
!!! tip "Заголовок"
    Текст подсказки.

!!! note
    Дополнительное замечание.

!!! warning
    Предупреждение.
```

### 3.8. Нумерованные списки-маршруты

```markdown
1. :material-1-circle: **Шаг 1** — описание.
2. :material-2-circle: **Шаг 2** — описание.
```

## 4. mkdocs.yml

### 4.1. Навигация

- В `nav:` — только видимые страницы.
- Правовые страницы (`legal/*.md`) в **навигации отсутствуют**, только футер.
- Сниппеты (`snippets/*.md`) — **исключены из сборки** через `exclude_docs`.

### 4.2. Редиректы (redirect_maps)

При перемещении страниц — добавлять запись в `redirect_maps`:

```yaml
redirect_maps:
  old/path.md: new/path.md
```

### 4.3. Структура nav

```yaml
nav:
  - Главная: index.md
  - Схемы:
      - Одноконтурное БСЗ: guide/schemes/single-circuit.md

      - kits/index.md
      - ...

      - components/index.md
      - ...
  - Видео-архив: videos/index.md
  - Контакты: contact.md
```

## 5. Стиль текста

- Тон: **технический, информативный, дружелюбный**.
- Адресация: **«вы»** (ты не используем).
- Термины:
  - **БСЗ** — бесконтактная система зажигания (определяем раз, далее — по аббревиатуре).
  - **КСЗ** — контактная система зажигания.
  - **Трамблёр** — распределитель зажигания.
  - **УОЗ** — угол опережения зажигания.
  - **ВВ** — высоковольтный.
- Англоязычные термины ссылаются на Wikipedia по запросу.
- Описания комплектаций: краткие, фактологические.

## 9. Правила добавления нового контента

### 9.1. Новый комплект (распределитель/автомобиль)

1. Создать страницу `docs/distributors/distributor-XXXX.md` (для трамблёра) **ИЛИ** `docs/kits/XXXX.md` (для автомобиля)
2. Добавить страницу в навигацию `mkdocs.yml` (под раздел «Распределители» или «Модели»)
3. Обновить таблицу в `docs/distributors/index.md` (если новый трамблёр)
4. Обновить грид в `docs/kits/index.md` (если новая модель)
5. Добавить фото в `docs/assets/wiki/...`
6. Добавить SKU и артикул на `mkdocs.yml` при необходимости

### 9.2. Новая инструкция

1. Создать страницу в нужной папке `docs/guide/`
2. Добавить в навигацию `mkdocs.yml` → раздел «Руководство»
3. Ссылка из `guide/index.md` → в грид карточек

### 9.3. Новая страница компонентов

1. Создать `docs/components/NAME.md`
2. Добавить в навигацию `mkdocs.yml` → раздел «Компоненты»
3. Обновить `docs/components/index.md` → грид карточек

### 9.4. Встраивание VK-виджета

1. Создать сниппет: `docs/snippets/vk-WHAT.md`
2. Вставить в целевую страницу: `--8<-- "snippets/vk-WHAT.md"`

## 11. Проверка сборки перед коммитом

**После любых изменений контента или конфигурации обязательно запускайте:**

```bash
mkdocs build --strict
```

> ❗ `--strict` включает режим, при котором **любые** ошибки (битые ссылки, отсутствующие страницы и т.д.) делают сборку неудачной.

Только после **успешного** прохождения сборки:

1. Проверить, что ошибок нет → `mkdocs build --strict` завершён без ошибок.
2. Сделать `git commit` с подробным описанием изменений.
3. Сделать `git push` / `deploy`.

**Если сборка упала — исправьте ошибки и запустите `mkdocs build --strict` снова до того, как сделаете commit.**

## 12. Что НЕ делать

- Никогда не удалять `legal/*.md` — они нужны для футера.
- Не изменять цвета без согласования (`#EE781C` — фирменный).
- Не удалять строчки `exclude_docs` и `not_in_nav` в `mkdocs.yml`.
- Не трогать скрипты аналитики и VK API в `overrides/main.html`.
- Не добавлять правовые страницы в `nav:` — они только в футере.
- Не использовать абсолютные пути к файлам в `docs/`.
